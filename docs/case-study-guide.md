# 📋 Guia de Apresentação de Case

> **Para quem é este guia?**
> Para qualquer designer que queira documentar seus projetos de forma profissional, convincente e que demonstre profundidade de raciocínio — não apenas resultado visual.

---

## ✅ Checklist Completo de Case Study

Use este checklist para garantir que cada projeto está bem documentado antes de torná-lo público.

---

### 1. 📌 Contexto & Briefing

- [ ] Nome e breve descrição do projeto
- [ ] Cliente, empresa ou contexto fictício bem definido
- [ ] Segmento/setor de atuação
- [ ] Seu papel no projeto (solo, equipe, liderança)
- [ ] Período de execução e duração
- [ ] Link para protótipo navegável no topo do documento

---

### 2. 🔍 O Problema

- [ ] Declaração clara do problema (How Might We / Como poderíamos?)
- [ ] Dados ou evidências que validam o problema
- [ ] Quem é afetado (persona ou segmento de usuário)
- [ ] Impacto do problema se não resolvido

---

### 3. 🎯 Objetivos

- [ ] Objetivos de negócio definidos
- [ ] Objetivos do usuário definidos
- [ ] Métricas de sucesso (KPIs) estabelecidas
- [ ] Restrições e limitações do projeto mencionadas

---

### 4. 🔬 Pesquisa & Descoberta

- [ ] Métodos de pesquisa descritos (entrevistas, benchmarking, analytics...)
- [ ] Número de participantes (se houver pesquisa com usuários)
- [ ] Principais insights resumidos
- [ ] Artefatos de pesquisa incluídos (mapa de empatia, jornada, personas...)
- [ ] Fluxogramas ou rascunhos iniciais incluídos *(processo > resultado!)*

---

### 5. 💡 Ideação & Processo

- [ ] Exploração de alternativas (pelo menos 2–3 caminhos considerados)
- [ ] Wireframes de baixa fidelidade incluídos
- [ ] Justificativa para as decisões de design tomadas
- [ ] Iterações e feedbacks de testes incluídos (se houver)
- [ ] User flow / fluxo de navegação documentado

---

### 6. 🎨 Solução Final

- [ ] Mockups ou telas finais em alta fidelidade
- [ ] Elementos do Design System documentados (cores, tipografia, espaçamento)
- [ ] Link direto para o protótipo navegável (Figma, Adobe XD...)
- [ ] Descrição de componentes-chave e suas decisões
- [ ] Acessibilidade considerada (contraste, tamanho de toque...)

---

### 7. 📊 Resultados & Aprendizados

- [ ] Resultados mensuráveis (antes vs. depois, quando disponível)
- [ ] Feedback de stakeholders ou usuários
- [ ] O que você faria diferente
- [ ] Próximos passos ou iterações futuras
- [ ] Reflexão sobre seu crescimento pessoal neste projeto

---

### 8. 📦 Entregáveis

- [ ] Protótipo navegável linkado
- [ ] Arquivos organizados na pasta `deliverables/`
- [ ] Assets exportados disponíveis em `assets/`
- [ ] README.md do projeto completo e revisado

---

### 9. 📬 Call to Action

- [ ] Convite para contato ou feedback ao final do case
- [ ] Links para redes sociais/portfólio
- [ ] Opção de deixar comentário (Issue do GitHub ou formulário)

---

## 🏆 Critérios de Qualidade

| Critério | ⭐ Básico | ⭐⭐ Intermediário | ⭐⭐⭐ Sênior |
|---|---|---|---|
| **Profundidade** | Mostra o resultado | Mostra o processo | Explica as decisões e trade-offs |
| **Pesquisa** | Benchmarking | + Entrevistas | + Dados quantitativos |
| **Visual** | Mockups finais | + Wireframes | + Rascunhos e iterações |
| **Resultados** | Projeto entregue | + Feedback recebido | + Métricas de impacto |
| **Narrativa** | Lista de features | História do problema | Jornada completa com aprendizados |

---

## 📝 Estrutura Recomendada de Narrativa

Um case poderoso conta uma história. Siga esta estrutura:

```
1. Contexto (onde estávamos)
   ↓
2. Problema (o que estava errado)
   ↓
3. Pesquisa (o que descobrimos)
   ↓
4. Ideação (o que tentamos)
   ↓
5. Solução (o que construímos)
   ↓
6. Resultado (o que mudou)
   ↓
7. Aprendizado (o que levamos para frente)
```

---

## 💡 Dicas de Redação

- **Use dados sempre que possível:** "reduzimos o abandono em 34%" é mais poderoso que "melhoramos a usabilidade"
- **Mostre o antes e depois:** comparações visuais são muito eficazes
- **Seja honesto sobre desafios:** mostrar como você lidou com obstáculos demonstra maturidade
- **Voz ativa:** "Eu conduzi entrevistas..." em vez de "Entrevistas foram conduzidas..."
- **Tamanho ideal:** 800–1500 palavras para leitura online confortável
